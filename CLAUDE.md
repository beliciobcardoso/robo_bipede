# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Learning-focused 8-DOF biped robot: SG90-clone servos, ESP32, MPU-6050 for balance. Per leg: hip pitch, knee pitch, ankle pitch, ankle roll (no hip yaw — turning only by asymmetric steps; no hip roll, kept by decision on 2026-10-24 — lateral weight shift = tilting the whole body ~18°, rocking gait). Approved leg dimensions (after sim F2, 2026-10-24): hips 45 mm apart, thigh = shin = 45 mm between axes, foot 40 × 70 mm, covers target 35 g / limit 50 g total — `BipedParams` defaults and `docs/arquitetura_perna.md`. Hardware/BOM status lives in `docs/lista_materiais.md` (user ticks what they own). Docs are pt-BR; code, identifiers and commits in English.

**CAD workflow is hybrid:** reference models of purchased parts (servo, bearings, screws) are generated by Python scripts here; **structural parts (brackets, legs, torso) are modelled by the user by hand in the FreeCAD GUI** — guide and review those, don't script them unless asked.

**Snap-fit covers:** the whole skeleton gets printed protective covers that clip on (no glue), enclosing servos, circuits and wires. Every structural part must be designed with the shared cover-mount interface from the start, leave envelope for the cover around each segment, keep access to ESP32 USB / power switch / battery charging / servo swap, and not limit joint range. Cover mass counts in torque budgets (sim F2/F4). Mount type decided 2026-10-24: **cantilever snap-fit clip + 2 locating pins per cover** (magnets = plan B); standard in `docs/capas.md`. Items in `docs/backlog.md` §3.1.

**Joint limits:** every joint has a mechanical stop printed in the part and a software limit 5° inside it (firmware and sim `ctrlrange`); the servo must never be commanded into a stop. Ranges in `docs/arquitetura_perna.md` (provisional until sim F5).

**Progress tracking:** `docs/backlog.md` is the single checklist of the project (who does each item: user / Claude / together). Tick items there when work lands, and add new ones there rather than in other docs.

**Simulation roadmap:** `docs/simulacao.md` (phases F0–F8). Stack: MuJoCo (CPU, viewer) + MJX/JAX and CuPy on the local RTX 3060 12 GB, all in the repo `.venv`. Policy: use existing open-source first, measure against the real robot, write our own algorithm only where nothing models it (SG90-clone servo model, CAD→MJCF bridge, gait generator, IMU filter, design sweeps) — never a physics engine. Each phase starts only when the mechanical design needs it.

**`sim/logs/` holds recordings of the user's monitor sessions: never delete them** (no wildcard `rm`); test runs by Claude go to `MONITOR_LOG_DIR` elsewhere, e.g. the scratchpad.

**`cad/manual/` is the user's hand-made work: read-only for Claude.** Never write, save, move, rename, delete or regenerate anything there (no `doc.save()` after opening, no `git checkout`/`clean`/`reset` that touches it). Analyse by opening with FreeCADCmd and only reading. The SG90 servo there (`cad/manual/servo_sg90.FCStd`) holds the authoritative re-measured dimensions; `cad/parts/servo_sg90.py` mirrors them for brackets to import.

## Commands

FreeCAD 1.1 is installed as a flatpak; everything runs headless through `FreeCADCmd`.

```bash
make              # build every cad/parts/*.py
make servo_sg90   # build one part (target = script basename)
make clean        # remove cad/build/
flatpak run org.freecad.FreeCAD cad/build/servo_sg90.FCStd   # open in GUI
```

Override the FreeCAD binary with `make FREECAD_CMD=...`. No tests or linter yet.

Python environment (analysis + simulation, pinned): `uv venv .venv && uv pip install --python .venv/bin/python -r requirements.txt`.

```bash
.venv/bin/python sim/tools/smoke_test.py   # MuJoCo CPU vs MJX GPU (JAX and Warp backends); must print SMOKE TEST PASSED
.venv/bin/python sim/tools/monitor.py      # viewer + exact crouch keys + live torque; logs every run to sim/logs/*.csv (read these to see what the user did)
.venv/bin/python sim/tools/monitor.py --sweep   # headless: every crouch depth -> knee torque, falls, joint-stop hits
.venv/bin/python sim/tools/build_biped.py     # regenerate sim/models/f1_biped.xml from BipedParams (mm, g) — never hand-edit that XML
.venv/bin/python sim/tools/f1_experiments.py  # F1: rise-speed peaks and one-leg stance search on the whole biped
.venv/bin/python sim/tools/rocking_test.py   # lateral rocking at walking pace, open loop: ankle-roll/knee peaks per step rate
.venv/bin/python sim/tools/f2_sweep.py [--quick]  # F2 design sweep on all CPU cores -> sim/results/f2_sweep.{csv,png}
```

Simulation gotchas (measured on this machine, F0/F1):
- No hip roll: with both feet down the ankle rolls are kinematically locked; standing on one foot means tilting the whole body ~18°. Don't model weight shift as a torso slide.
- Always ramp posture changes (servo-like speed); jumping the targets makes the boxes robot fall and gives misleading torques.
- Open-loop rocking is too sensitive to the motion pattern to rank designs; F2 uses the physics estimate m·g·(spacing/2) + I·α for the weight shift (conservative vs sim). Design sweeps over geometry run per-CPU-core (different model per point); keep the GPU for many runs of one model.
- Joint damping 0.017 N·m·s/rad = SG90 stall torque / no-load speed (torque lost with speed). Moving-torque peaks are sensitive to it (0.05 inflated them ~30 points) — keep it until F3 measures the real servo.
- Use MJX with `impl="warp"` and `graph_mode=JaxCallableGraphMode.WARP` (from `warp._src.jax.ffi`). The default graph mode fails with `CUDA_ERROR_NOT_SUPPORTED` (nested CUDA graphs); WARP mode is also the fastest (~4.7 M steps/s at 16k robots vs ~0.2 M for `impl="jax"` and ~70 k for one CPU core).
- Warp preallocates for the whole batch: pass `naconmax` (≈ contacts per robot × batch) and `njmax` to `mjx.make_data`.
- Set `XLA_PYTHON_CLIENT_PREALLOCATE=false` before importing JAX, or it grabs 75 % of the 12 GB VRAM.
- MuJoCo units are SI (m, kg, s, N·m); CAD is in mm — convert at the bridge.

Comparing two models (e.g. a hand-made part vs its scripted reference) — GPU volumetric diff via CuPy:

```bash
flatpak run --env=SRC=$PWD/cad/manual/servo_sg90.FCStd --env=OBJ=Body --env=OUT=$PWD/cad/build/a.stl \
  --command=FreeCADCmd org.freecad.FreeCAD tools/export_stl.py          # read-only on SRC
.venv/bin/python tools/compare_meshes.py cad/build/a.stl cad/build/b.stl --names "seu,script" --png cad/build/diff.png
```

`compare_meshes.py` casts one Z ray per XY column (default 0.05 mm), gets exact crossings and diffs the inside intervals; volumes are exact in Z (validated: matches FreeCAD's solid volume). Don't use `Shape.cut/common` or `isInside` sampling for this — booleans fail on coincident faces and sampling is far too slow on filleted parts.

## CAD architecture

- One script per part in `cad/parts/<part>.py` → `cad/build/<part>.FCStd` + `.step`. `cad/build/` is gitignored; scripts are the source of truth. Output dir comes from env `CAD_OUT_DIR` (Makefile sets it).
- Script shape (follow `servo_sg90.py` / `bearing_623zz.py`): a frozen `@dataclass` of dimensions exposed as module-level `DIMS`, a `build(doc, d=DIMS)` returning the final object of a CSG tree, and `main()` calling `export_part`. Other parts are meant to import `DIMS` to derive pockets/holes.
- `cad/cadlib.py` holds the shared helpers: `add_box` / `add_cylinder` / `add_tube` / `cut` / `fuse` create `Part::*` document objects (so the tree stays inspectable in the GUI), and `export_part` recomputes, validates a single valid solid, and writes FCStd + STEP. Part scripts put `cad/` on `sys.path` themselves because FreeCADCmd doesn't add the script dir. The Makefile rebuilds every part when `cadlib.py` changes.
- Geometric constraints are encoded as derived `@property`s rather than duplicated numbers (e.g. `shaft_offset = tower_d / 2` because the gear tower is flush with the case wall).
- Dimensions of purchased parts come from caliper measurements recorded in `docs/medidas_<part>.md`; unmeasured values are commented `nominal`. Keep the doc and the dataclass in sync when a value changes.
- **Servo coordinate frame** (shared by every part that mounts a servo): origin on the output shaft axis at the tab underside (seat plane), +Z toward the shaft, +X along the body from the shaft end. The SG90 clone's cable exits on the shaft-side end face.
- Cover mount reference: `snap_clip.py` (cover half) and `snap_socket.py` (skeleton half) share `SnapDims` and an assembled-position frame (skeleton top face z = 0, side face y = 0, cover pushed down −Z). `snap_socket` builds the cover half too and fails if they overlap; the Makefile rebuilds it when `snap_clip.py` changes.
- Joint pivots: a 623ZZ bearing opposite each servo shaft, M3 screw as pin. `BearingDims` carries the abutment limits (`da min` / `Da max`) that spacers and housing shoulders must respect so they touch only the correct ring.

## FreeCADCmd gotchas

- It **exits 0 even when the script raises**. The Makefile detects failure by grepping for `Exception` and checking the output file exists — keep that when changing the build.
- A script file runs with `__name__` equal to its module name, not `"__main__"` — the same value an import gives. Guard with `if run_as_script(__name__, DOC_NAME):` (cadlib; checks the script path in `sys.argv`), so parts can import each other's DIMS without re-running the other part's build.
- The flatpak has a private `/tmp`: scripts and files passed to `FreeCADCmd` must live under `$HOME` (e.g. inside the repo), never `/tmp`. Pass inputs via `flatpak run --env=VAR=...`.
- `doc.saveAs` over an existing file leaves `.FCBak` backups; `export_part` deletes the old `.FCStd` first.
- Headless visual check: tessellate the shape (`Part.read(step).tessellate(0.1)`) and render with matplotlib (bundled in the flatpak's Python) to a PNG.
